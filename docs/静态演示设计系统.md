# 流动圈静态演示设计系统

> 状态：开发交接版 v0.1
>
> 日期：2026-07-15
>
> 运行中的样式事实来源：`../app/globals.css`
> 组件与交互事实来源：`../app/page.tsx`

## 1. 品牌表达

- 中文暂名：**流动圈**。
- 英文识别：**FLOW CIRCLE**，不再使用“LIU DONG”拼音。
- 核心句：**可以问，也可以拒绝。**
- 产品不是银行、积分榜或履约平台，而是一层轻量社区记忆。
- 视觉中的游戏感用于降低开口和记录的门槛，不制造排名、连胜、签到或竞争。

## 2. 视觉关键词

- Neo-brutalism；
- 奶油纸张底色；
- 粗黑描边；
- 硬边黑色阴影；
- 高饱和黄色世界背景与蓝色点阵；
- 粉、蓝、绿、珊瑚红分别承担不同事件语义；
- 圈子像营地或地图，成员像社区角色；
- 元素可以有轻微“不完美”的圆角和手作感，但信息必须对齐。

## 4. 排版

- 主字体：`ui-rounded` → `Arial Rounded MT Bold` → `Trebuchet MS` → `Microsoft YaHei` → 系统无衬线。
- 数据标签与英文 eyebrow：系统等宽字体。
- 大标题紧凑、粗重，允许轻微负字距；说明文字保持正常行距。
- 重要数字必须同时带名称和单位，不能只展示正负数。
- 中文优先；英文只承担地图标签、角色卡和界面节奏，不替代核心中文信息。

## 5. 布局系统

### 桌面

三列结构：

1. 左侧圈子地图，宽约 250px；
2. 中间完整手机应用，宽 520—720px；
3. 右侧今日世界、参考物和价值提示，宽约 280px。

中间应用使用固定顶部、圈子切换、可滚动内容和底部导航。左右两侧在视口中保持吸附。

### 平板与手机

- 1180px 以下隐藏右侧世界面板；
- 850px 以下隐藏左侧圈子地图，只保留完整应用；
- 手机端底部导航固定；
- 560px 以下多栏卡片切成单列，弹层从底部进入；
- 手机宽度下禁止横向页面滚动，局部标签行可以横向滚动。

## 6. 组件规范

### 6.1 圈子卡 / 营地卡

- 必须展示圈子名称、当前用户余额、圈内角色或加入方式；
- 粉、黄、蓝用于三个示例营地，但颜色不是永久身份；
- 点击圈子卡切换当前圈子；点击营地介绍进入完整介绍页；
- 介绍页包含“为什么存在、适合谁、营地约定、加入方式”。

### 6.2 事件卡

| 类型 | 颜色 | 必须内容 |
| --- | --- | --- |
| 我想要 | 粉 | 人、完整需求、时间/地点、可见范围 |
| 我可以给 | 绿 | 人、完整提供、时间/地点、可见范围 |
| 互助完成 | 黄 | 双方、事情、额度、圈子、状态 |
| 神秘记录 | 蓝 | 类型、额度、时间；隐藏人物和故事 |
| 好人卡 | 珊瑚红 | 发卡人、接收人、具体故事、日期 |

事件详情必须有返回/关闭路径，并能去成员主页或生成分享图。

### 6.3 角色头像

- 头像不是同一张模板换一个字；当前有 8 种造型：`crop`、`wave`、`cap`、`bob`、`spike`、`curl`、`bun`、`leaf`。
- 造型通过头发、眼睛、嘴型、颜色和角标组合区分。
- 大头像 54px，小头像 39px；均使用粗黑圆形描边和硬阴影。
- 名字首字只做识别辅助，不能成为唯一差异。

### 6.4 按钮

- 主要按钮：黄色底、3px 黑边、小硬阴影；
- 次要按钮：奶油底、3px 黑边；
- 筛选标签：胶囊形 2px 黑边，选中时使用黄色；
- 底部导航：五等分，每一项之间都有 2px 竖线，包括“圈子”左侧；
- 所有看起来可点击的元素都必须有动作，不保留无响应按钮。

### 6.5 弹层

- 桌面最大宽度 560px，完整资料弹层最大宽度 720px；
- 手机端变为底部抽屉；
- 右上角始终提供明确关闭按钮；
- 点击遮罩关闭；
- 长内容在弹层内部滚动，不让页面横向溢出。

### 6.6 完整成员档案

三个固定标签：

1. 好人卡：完整故事、发卡人、日期、圈子和标签；
2. 需要 / 提供：标题、完整说明、时间、地点、参考、范围与状态；
3. 互助记录：双方、额度、圈子、日期、可见范围和确认/更正/撤销状态。

档案底部展示各圈独立余额；其他成员只能看到允许公开的记录，本人能看到私密与撤销状态。

## 7. 状态语言

- 正数：我曾向社区给出，不表达“更优秀”；
- 负数：我曾接受社区帮助，不表达信用污点；
- `active`：进行中；
- `paused`：已暂停，仍保留历史；
- `closed`：已结束；
- `confirmed`：已确认；
- `corrected`：已更正，保留状态痕迹；
- `rejected`：已撤销，不进入正常公开流。

避免使用“扣款、欠款、征信、违约、信用分”等金融化或惩罚性语言。

## 8. 交互原则

- 首页打开即是综合圈子动态，不是宣传首页；
- 桌面侧栏品牌标识和手机顶栏“流”图标都进入独立的整体概念页；
- “说一句”是统一入口，先生成草稿，确认后才进入演示流；
- 发现页筛选真实改变列表，不只改变按钮颜色；
- 首页筛选支持全部、互助、需要、提供和好人卡；
- 圈子介绍、规则、全部成员和邀请必须可打开；
- 成员头像、动态详情、分享、联系、创建圈子和公开设置都有反馈；
- 所有静态动作明确标注“静态演示”，避免被误认为真实保存或真实发送。

### 8.1 整体概念页

- 概念页是应用内视图，保留顶栏和底部主导航，不使用一次性宣传弹窗；
- 首屏一句话说明产品定位，随后依次解释四个不同对象、一次互助的流程、示例圈子和明确边界；
- “圈子、互助额度、需要 / 提供、好人卡”必须分开表达，不把社区记忆、发布内容和认可故事合并成同一种积分；
- 示例圈子卡片读取演示数据库并进入对应圈子页，不另写一套脱离数据的介绍；
- 桌面采用两列概念卡，手机改为单列；手机宽度下不得横向溢出。

### 8.2 创建圈子页

- 创建圈子使用应用内独立页面，不使用简化弹层；
- 固定分为四步：圈子身份、互助设置、成员与边界、预览确认；
- 必须明确区分互助额度、需要 / 提供和好人卡，且默认写明“不兑换人民币、不做贡献排名”；
- 场景、加入方式、可见范围、参考物和隐私选项会真实进入最终预览；
- 保存后展示静态完成状态，并明确说明不会建立真实账户、数据库或邀请链接。

## 9. 无障碍与质量基线

- 键盘焦点使用 4px 白色外框；
- 关键图标按钮提供 `aria-label`；
- 颜色不能是唯一状态信息，必须同时出现文字；
- `prefers-reduced-motion` 下关闭过渡；
- 手机端不出现横向页面滚动；
- 页面构建、静态渲染检查与代码检查必须通过；
- 新增可点击元素后，检查是否存在没有处理动作的 `<button>`。

## 10. 开发拆分建议

正式开发可把当前单页拆为：

- `CircleSwitcher`
- `ActivityFeed` / `ActivityCard`
- `Composer`
- `CircleProfile`
- `MemberDirectory`
- `MemberArchive`
- `GoodCardList`
- `ListingList`
- `TransactionList`
- `InviteFlow`
- `SharePoster`

设计 token 可先迁移为 CSS variables 或 design-token JSON；业务数据结构以《静态演示数据库》为产品参考，再单独完成权限与持久化设计。
