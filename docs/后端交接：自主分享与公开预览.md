# 后端交接：自主分享与公开预览

日期：2026-10-03。前端 UI 预览已把分享入口限制为本人主动操作：本人发布且仍有效的「我想要／我可以给」、本人参与且已确认并没有待处理更正的单条互助记录，以及别人写给本人的好人卡。其他人的需要／提供以「联系发布者」为主要操作。UI 测试使用虚构数据；当前单条内容通过完整图片保存或手机系统发送。下面的公开链接能力尚需后端提供，不能把本地 `?post=` 链接当作对外公开分享，因此单条分享图暂不附二维码。

## 分享规则

1. 查看动态不等于允许分享。他人的需要／提供、写给其他人的好人卡，以及待确认、正在更正、已撤销的互助记录不提供单条分享入口。收卡人可主动分享写给自己的好人卡；写卡人不能代替收卡人公开。
2. 本人点击某条内容的「分享」时，分享图直接展示本人选择的文字，不再生成「登录后查看」占位图。圈内发布内容也需这一次明确的分享操作，才能对外展示该条内容。
3. 分享只针对选中的单条内容，不连带公开整个圈子的动态、成员名单、账户余额或其他记录。互助记录涉及另一方，公开预览应默认避免附带对方的联系方式；具体故事文本由分享者确认。
4. 内容暂停、结束、被撤销，或者分享者撤回公开分享后，公开链接应失效或显示明确的已失效状态。已导出的图片无法远程撤回，界面应让用户在导出前看到完整预览。

## 需要后端提供

- 创建单条公开分享：校验当前登录者是需要／提供的发布者、已确认互助记录的当事人，或好人卡的收卡人；返回不可猜测的分享 token／URL。不能只凭客户端隐藏按钮来控制权限。
- 无需登录的访客预览：按分享 token 返回经发布者主动选择的单条内容与必要的作者资料；不要返回圈内原始档案、余额、其他动态、完整 bootstrap 数据或联系方式。
- 撤回与状态同步：分享者可撤回；源内容状态改变时，访客预览同步失效。重复点击分享可以复用或明确更新同一条分享，避免产生不可管理的多个公开版本。
- 创建分享后返回可用于二维码、复制链接和系统分享的正式 URL。当前前端的 `/?post=<source>:<id>` 仍走登录后的可见数据，并不是这个契约的实现；接入正式 URL 后再为单条分享图加回二维码与链接操作。

## 验收

使用独立 A、B 身份及未登录访客：A 可分享自己仍有效的需要／提供和自己参与的已确认记录；B 写给 A 的好人卡可由 A 分享，B 不能代替 A 分享；B 不能创建 A 的发布内容分享。未登录访客凭有效 token 只能看到该单条内容；普通 `?post=` 深链仍遵守圈子权限；暂停、撤销或主动撤回后 token 失效。分别验证分享图、二维码、复制链接和手机系统分享使用同一个正式 URL。
