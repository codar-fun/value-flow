# 流动圈后端与泡泡助手配置

## 已经接通的能力

生产数据保存在 Cloudflare D1。首次启动时会自动创建表并放入原型中的示例数据，之后页面从数据库读取，不再把前端数组当作真实数据源。

目前接口覆盖：

- 页面启动与当前身份；
- 发布需要、提供、好人卡；
- 已完成互助入账与双方账户更新；
- 创建圈子、创建者成员关系和初始账户；
- 限时单次邀请凭证；
- 跨圈公开设置；
- 泡泡助手草稿整理与对话留档。

身份优先使用 Sites 转发的已登录用户。第一次正式访问时，站点会把原型中的“俏也”资料认领给第一个已登录用户；本地开发没有登录头时继续使用 `qiaoye`，方便调试。

## 配置泡泡助手

项目根目录的 `.env.example` 是唯一需要复制的模板：

```text
BUBBLE_ASSISTANT_API_URL=
BUBBLE_ASSISTANT_API_KEY=
BUBBLE_ASSISTANT_MODEL=
BUBBLE_ASSISTANT_SYSTEM_PROMPT=
```

本地开发时复制为 `.env.local` 并填写。线上值通过 Sites 的运行环境设置，不要把真实密钥提交到仓库。

接口需要兼容 OpenAI Chat Completions 请求与响应格式。`BUBBLE_ASSISTANT_API_URL` 必须是 HTTPS 完整地址；`BUBBLE_ASSISTANT_SYSTEM_PROMPT` 可留空，留空时使用项目内置的边界提示词。

未填写上述三项必需值时，泡泡助手会使用内置整理器。这样创建圈子、发布、邀请、账户和设置等其余功能不会被 API 配置阻塞。

## 数据与安全边界

- API 密钥只由服务端读取，不返回浏览器。
- 所有写操作都由服务端确认当前成员身份与圈子成员关系。
- 交易额度只接受正整数，且双方必须是同圈的不同成员。
- 神秘记录在动态中隐藏双方身份与具体故事。
- 原始交易保留状态字段，为后续拒绝、更正与审计界面提供基础。
- D1 迁移位于 `drizzle/`，部署时随站点版本一起发布。
