# 流动圈：当前开发交付说明

> 更新日期：2026-08-21
> 当前分支：`codex/value-flow-sync`
> 线上地址：<https://flow.sola.day>
> 状态：产品验证与小范围多人测试，不是可直接开放给真实社区的稳定账本。

## 1. 当前结论

前端已经完成从旧 D1 / 静态原型到 loop-backend 的迁移。邮箱身份、多圈成员关系、互助记录、余额、需要 / 提供、通知、邀请和个人资料都来自同一个 Phoenix + PostgreSQL 后端。

本轮真实 A/B 双账号测试暴露并修复了多项前端流程和移动端视觉问题；同时发现一项未由前端修复的 P1 后端账本一致性问题：已更正记录撤销后，记录消失但余额没有回滚。

## 2. 当前架构与部署

- Next.js 16 App Router、React 19、TypeScript；
- Vinext + Vite 构建，Worker-compatible 服务端入口；
- loop-backend 是唯一身份和业务数据源；
- 前端同源 API route 负责请求校验、cookie session 和 loop 接口映射；
- `db/runtime.ts` 是数据适配层，不是数据库运行时；
- 生产域名 `flow.sola.day` 由 `ginger.yml` 中的 `flow-circle` 服务发布；
- 生产后端默认是 `https://loop-api.sola.day/api`；
- `.openai/hosting.json` 仍是当前 Vinext / Sites 构建配置的一部分，但不代表业务数据保存在 D1。

## 3. 身份与权限

- 生产使用邮箱 OTP，没有匿名 `qiaoye` 回退；
- access / refresh token 仅放在 httpOnly cookie；
- 前端 test auth 仅能在非 production、连接 localhost 后端且配置真实本地 token 时开启；
- test auth 只改变登录便利性，不改变 membership、圈主权限、余额、通知、可见性和交易权限；
- 多用户并发测试应使用不同浏览器 profile / 无痕会话，避免 cookie 串号；
- 联系方式只向同圈成员显示；他人档案只返回共同圈数据。

## 4. 主要页面与对象

### 页面

- `/`：动态、发现、记一笔、圈子、我的和所有站内弹层；
- `/join/[token]`：邀请落地、登录后接受邀请；
- `?profile=<member-id>`：成员档案深链接；
- `?post=<kind:id>`：动态深链接；
- `/api/*`：前端同源代理。

### 业务对象

- Account / Member：身份、资料、头像和同圈联系方式；
- Circle / Membership / Circle account：圈子、成员角色、余额和累计给出 / 收到；
- Record：互助记录、确认、更正、拒绝 / 撤销；
- Listing：需要 / 提供；
- Good card：不改变余额的好人卡；
- Invitation / Join request / Notification：邀请、审批和处理入口。

- 圈子切换条在手机上可横滑但不显示粗系统滚动条。

### 圈子、记录和安全确认

- 圈子图标不再使用单字母，提供自然、科技、旅行、文化主题；
- 创建 / 编辑圈子的参考物、规则和整数额度增加前端校验；
- 圈主转让、成员退出、记录撤销 / 拒绝改为站内确认弹窗；
- 多层弹窗按 Esc 只关闭最上层；
- 动态筛选空状态、空字段和长昵称显示得到修复。

### 分享、二维码和深链接

- 个人档案、动态和邀请均可生成带真实二维码的海报并保存为 PNG；
- 点击动态分享时分享对应动态，不再错误生成当前用户档案；
- 圈内私密正文不会印在可外发卡片上；
- 无权限或失效的 profile / post 参数会被清理并给出说明。

### 头像和品牌图形

- Logo 使用无文字、无字母的四色拼贴图形；
- 注册后按账号 ID 稳定分配 8 个彩色抽象系统头像；
- 用户可在资料中切换系统图案或定制人物头像；
- 人物头像支持 16 种发型、8 种发色、7 种眼睛、5 种眼镜、6 种嘴巴和 4 种浅色到暖黄色肤色；
- 右下角贴纸 / 标记已从产品中移除；
- 人物与系统图案选项不显示名称，只通过图形选择并保留无障碍标签；
- 系统头像用单一 SVG 圆形裁切和单一外框，避免漏色、双线和局部边缘加厚。

## 7. P1 后端问题

路径：

```text
pending → confirmed(4) → corrected(6) → rejected
```

撤销返回成功，记录从双方列表消失，但账户仍为 `+6/-6`。两个独立会话重新读取 bootstrap 后结果一致。没有经过更正的已确认记录可以正常撤销回滚。

前端 `PATCH /api/transactions/:id` 仅代理 `PATCH /records/:id {action:"reject"}`，余额完全展示 loop-backend 返回的 `circle_accounts`。因此不得在前端用“按可见记录重算余额”掩盖问题；后端应在同一数据库事务中冲销当前有效金额并更新状态。

完整交接见 [`后端问题：已更正记录撤销后余额未回滚.md`](后端问题：已更正记录撤销后余额未回滚.md)。
