# 流动圈可运行版本：开发交付说明

> 状态：版本 9 已发布
> 日期：2026-07-17
> 线上地址：<https://liudong-circle-demo.helloworld-zoey.chatgpt.site>

## 1. 当前结论

项目已经从静态交互原型进入第一版可运行网页：业务数据保存在 Cloudflare D1，页面通过服务端 API 读取和写入，主要流程可以跨刷新保留。

它仍是产品验证版本，不是正式生产系统。最大的未完成项不是页面数量，而是正式身份、真实成员权限、敏感数据处理、通知与运营恢复能力。

## 2. 当前架构

- Next.js 16 App Router、React 19、TypeScript；
- Vinext + Vite 构建；
- Cloudflare Worker 运行；
- Cloudflare D1 持久化；
- Drizzle 定义数据结构并生成迁移；
- OpenAI Sites 托管与发布；
- 外部泡泡助手使用兼容 Chat Completions 的服务端代理；
- 未配置外部模型时使用内置整理器。

## 4. 已实现的业务流程

### 数据加载与身份

- Worker 将 D1 与服务端环境交给应用；
- 首次访问会创建表并写入原静态原型的示例数据；
- Sites 提供用户邮箱时按邮箱识别成员；
- 第一个正式登录用户会认领示例资料 `qiaoye`；
- 本地或匿名无身份信息时回退到 `qiaoye`。

最后一条只为开发便利保留。当前站点是公开的，所以匿名访问者可能共用同一身份。这是下一轮必须先修的上线阻塞项。

### 需要、提供和好人卡

- 泡泡助手先把自然语言整理为可检查草稿；
- 用户确认后写入数据库和动态流；
- 需要/提供可以暂停或恢复；
- 好人卡不改变余额。

### 互助交易

- 只记录已经完成的互助；
- 提供者增加额度，接受者减少额度；
- 写入时验证双方属于同一圈且不是同一个人；
- 当事人可以拒绝或撤销；
- 撤销时恢复双方余额并从正常动态流移除；
- 数据库保留原记录及状态痕迹。

### 圈子与邀请

- 创建圈子会同时建立创建者 membership、初始账户和规则；
- 邀请令牌只在数据库保存哈希；
- 默认 7 天有效、最多使用一次；
- 直接加入模式立即创建成员与账户；
- 审批模式写入 pending 成员关系，但管理员审批界面尚未实现。

### 设置和分享

- 跨圈好人卡、需要/提供和隐藏内容设置会持久化；
- 系统分享已接入；
- 当前“分享图”仍主要是视觉预览，没有生成可下载的真实图片或二维码。

## 6. 权限与隐私现状

已经具备：

- 写操作在服务端解析当前身份；
- 写圈子数据前检查 active membership；
- 交易双方必须是同圈成员；
- 私密交易只返回给当事人；
- 非本人成员资料只返回与当前用户同圈的成员；
- API 密钥不发送给浏览器。

仍需补齐：

- 正式登录与匿名访问策略；
- 管理员角色和审批权限；
- 联系方式更细的服务端按需读取；
- 成员退出、导出、删除和撤回同意；
- 邀请滥用、速率限制和审计日志；
- 敏感数据保留期和事故响应；
- 多人并发更正同一笔交易时的事件锁与幂等控制。

## 7. 路由现状

- `/`：主应用；
- `/join/[token]`：邀请落地页；
- `/api/*`：数据与业务接口。

主应用内“动态、发现、圈子、我的、关于、创建圈子”仍由客户端 `view` 状态切换，因此刷新会回到默认动态，成员详情和单圈页面暂时不能深链。
