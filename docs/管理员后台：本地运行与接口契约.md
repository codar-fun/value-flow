## 页面与分工

本仓库`/admin`提供独立的管理员工作台。管理员密码登录→查询圈子→选择真实圈内成员→逐人填写期初积分→核对后端预览→确认发放→查询批次/刷新余额→退出。空白不发放，0是显式初始化；每个成员账户只初始化一次。圈主仅联系管理员，无发放权限。

已实现：页面、独立admin会话代理、列表分页、预览逐项核对、重复请求的批次键、结果不确定时锁定原批次供查询/重试、历史查询、错误状态和移动布局。密码不写死，真实登录必须由后端校验；前端不维护业务账本。后台仅本地开发显式启用，生产构建的管理代理始终关闭，主站无管理入口。

维护方已声明交付：密码开通/重置/限流/会话撤销、平台管理员授权、圈子/成员读取、期初账本和事务/幂等、预览版本锁、批次查询与纠错审计；本地仍需按 L13 验证。前端暂未实现纠错表单，后端已提供 opening-balance-adjustments 接口，仍需交付受控纠错runbook；批次记录可查询但暂无CSV导入/导出按钮。

## 本地启动

安装依赖后，在被忽略的`.dev.vars`中配置（有原文件时仅增改对应项，不要覆盖其他配置）：

```dotenv
FLOW_ADMIN_ENABLED=true
LOOP_ADMIN_API_BASE=https://flow-api.sola.day/api
```

此地址是后端API根路径，代理自行拼接`/admin/...`。运行`pnpm dev`，打开`http://localhost:3000/admin`。管理员密码由维护方开通，在页面输入，不保存到本地配置。主站邮箱OTP cookie不能登录此后台。未开通账号或密码不正确时，后端会拒绝登录；接口缺失才显示未接通。

本地开发服务以当前Vinext实际输出的loopback地址为准。本轮本机实际监听localhost的IPv6回环，`127.0.0.1`并未监听；使用终端输出的localhost地址。生产构建不能用来启动此本地后台。

## 精确接口与响应

浏览器只请求`/api/admin/...`，本地服务代理到`LOOP_ADMIN_API_BASE/admin/...`。所有响应JSON、`Cache-Control:no-store`；后端返回400/401/403/409/422/429及错误对象`{"error":{"message":"可展示错误"}}`。404/405由代理转换为“后端接口未接通”。禁止返回200但忽略写入字段。

### 管理员认证

- `POST /admin/session`请求`{"password":"用户输入"}`；响应`{"access_token":"后端签发token","expires_in":900,"admin":{"name":"管理员名称"}}`。本地代理只将token放入独立HttpOnly、SameSite=Strict cookie，返回浏览器的JSON不含token/password。HTTPS时加Secure；本地HTTP用于loopback开发。
- 后续请求代理使用`Authorization: Bearer <admin token>`。后端逐次验证平台管理员身份，不能把member或圈主token当管理员token。
- `GET /admin/session`响应`{"authenticated":true,"admin":{"name":"管理员名称"}}`；失效返回401。
- `DELETE /admin/session`撤销后端token，响应`{"ok":true}`或204；代理清本地admin cookie，不影响普通OTP会话。前端写请求必须同源Origin；过期会话需重新登录，无自动续期。

### 圈子和成员

- `GET /admin/circles?q=<关键词>&cursor=<下一页>`：`{"circles":[{"id":"circle-id","name":"社区圈","currency":"积分"}],"next_cursor":null}`。
- `GET /admin/circles/:id/members?cursor=<下一页>`：`{"members":[{"account_id":"account-id","display_name":"成员名","username":"唯一账号名","balance":10,"opening_balance":null,"opening_balance_initialized":false}],"next_cursor":null}`。
- `opening_balance_initialized`必须明确返回boolean，不能靠余额是否为0判断已初始化；输入0也属于已初始化。只返回已加入的真实成员，注册但未加入者不在此列表。next_cursor为字符串或null。

### 预览和发放

- `POST /admin/circles/:id/opening-balance-imports/preview`：采用H09请求`idempotency_key/source/as_of_date/note/entries[{account_id,opening_balance}]`。
- 响应`{"preview_id":"preview-id","expires_at":"2026-10-03T10:00:00Z","total":300,"entries":[{"account_id":"account-id","display_name":"成员名","current_balance":10,"opening_balance":300,"resulting_balance":310}]}`。
- 前端核对成员集合、金额、总额与“当前余额+期初=发放后余额”，不匹配不允许确认。服务端仍须自己验证权限、范围、版本与总额，不能依赖这些前端校验。
- `POST /admin/circles/:id/opening-balance-imports/:preview_id/confirm`：请求`{"idempotency_key":"预览请求的同一键"}`；响应`{"batch":<下述批次对象>}`。完成状态必须为completed。对同一已完成预览重试返回原批次，不重记账。
- `GET /admin/circles/:id/opening-balance-imports?cursor=...&preview_id=...`：响应`{"batches":[<批次对象>],"next_cursor":null}`。preview_id过滤用于响应丢失后的结果查询，必须按该预览返回；无记录不能解释为已撤回或未写入。
- `GET /admin/circles/:id/opening-balance-imports/:batch_id`：代理已允许，后端交付单批次读取；当前页面用列表/预览过滤查询。

批次对象：

```json
{
  "batch_id": "batch-id",
  "preview_id": "preview-id",
  "idempotency_key": "与预览一致的键",
  "status": "completed",
  "source": "社区原有积分台账",
  "created_at": "2026-10-03T09:00:00Z",
  "total": 300,
  "entries": [
    {"account_id":"account-id","display_name":"成员名","opening_balance":300,"resulting_balance":310}
  ]
}
```

批次中的resulting_balance是发放当时的余额快照；不是后续实时余额。列表也可返回pending/failed状态。确认成功与查询成功前端均核对原preview_id、幂等键和条目，不能把别的批次显示为本次完成。
