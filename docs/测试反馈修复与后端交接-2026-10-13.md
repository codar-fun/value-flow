## 自动标签如何处理旧数据

`app/lib/content-search.ts` 是可读的关键词分类器，不调用 LLM，不写入别人帖子或改动原文。无已选类别时对当前可见正文生成标签，未命中为“其他”；作者选择的类别优先。地点仅来自原有 location、作者明确选的地点标签、或正文明确提到的受支持城市，表示内容提及地点，不代表作者住址。自定义标签支持 `地点:苏州` 等形式。

旧帖自动标签是展示层派生结果；新发布、修改时将选定标签提交后端。互助已有 tags，listing 已有 tags，好人好事需要后端补 tags 保存和读回。若后端返回成功但读回缺少标签 / 图片，页面保留持续核对提示，说明内容已发布，不鼓励重复发布。

## 后端接续 1：分享入圈申请

新分享链接示例：`/?post=listing%3A<id>&circles=<circle-id>`，二维码不需要创建旧的公开预览 token。circle query 只是导航提示，后端必须独立验证内容真实存在、有效状态及圈子归属。跨圈帖分享图最多带三个入圈候选，已入圈用户以自己实际可见的帖子范围定位。

1. `GET /circles/:id/preview?shared_post=listing:<id>`（同源前端 `sharedPost`，代理转换为 `shared_post`）。兼容 `transaction:<id>`、`card:<id>`。允许登录且未入圈的持链接者看最小圈子介绍和申请状态；不返回帖正文、联系方式、成员名单、余额。仅邀请圈也要支持这一申请入口。
2. 在现有圈子 preview 响应增加 `shared_entry_supported: true`；支持分享申请时 `can_apply: true`。必须验证帖与圈子关系、帖子尚有效、不是隐藏 / 神秘 / 私密内容。失败返回 403 / 404 / 410 和可读错误。
3. `POST /circles/:id/join` 接收 `{shared_post, join_mode:"approval", note?}`。这一入口统一创建 pending 申请，任何圈子都不能自动加入。幂等重复申请返回 pending；已经 active 则应在 preview 明确返回 active，不重复提交。
4. pending 不可读帖子；圈主同意后才改变 membership，新的 bootstrap 按既有权限返回原帖，前端继续定位。用户撤回申请沿用 DELETE join。
5. 前端代理在写入前预检 `shared_entry_supported`；服务未交付则返回 501，不向旧服务发送会被误当成直接入圈的请求。若服务违约返回 active，报结果不符合审批流程，不能当成功通过。

旧 `/s/:token` 是之前主动创建的公开单条预览机制。本轮没有替历史链接伪造入圈限制，没有迁移 / 收回历史 token；如需改变历史公开预览语义，应由后端明确迁移并另行验收。新 UI 已切换为受入圈权限约束的链接。

## 后端接续 2：三图附件

建议采用下列前端已接入的精确契约，不能只提供上传入口而遗漏读回与权限。

| 后端 | 内容 |
| --- | --- |
| `POST /listing-images` | 登录必需，multipart `{file, upload_key}`；成功 201 `{id}`。同用户同 upload_key 重试返回同一个附件；最多 5 MB，仅解码验证后的 JPG / PNG / WebP，不仅信 MIME / 扩展名。去 EXIF，防止地址等照片元数据外泄 |
| `GET /listing-images/:id` | 返回真实图像字节及正确 Content-Type；上传者能看未关联草稿图；关联后按帖可见性和圈子权限校验。未登录 / 圈外 / 猜 ID 都不能读，隐藏、暂停、结束和删除后的权限也需核对 |
| `POST /listings` | 增加 `image_ids`，最多 3 个不同 ID。验证附件归上传者所有，原子关联帖子；不支持 / 非本人 / 不存在的附件应明确拒绝，不能忽略后成功创建 |
| `PATCH /listings/:id` | 同上，数组为空可移除；不能改别人的帖子，不能关联他人未授权附件 |
| `GET /bootstrap` | 可见 listings 返回 `image_ids`；与写入顺序一致；供编辑、详情和重开草稿使用 |

图片不进入公开海报。浏览器通过同源 `/api/listing-images/:id` 登录后读图；代理使用 `private, no-store`，不暴露外部私有存储直链。存储由 flow-backend 决定，当前前端没有伪造对象存储或上传成功。后端需约定未关联附件保留期和垃圾回收，兼顾已保存草稿。
