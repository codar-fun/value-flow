# 社区货币 — 开发需求文档

> 这不是一篇待写的文章，而是一份**开发需求**：说明为什么要做社区货币、它应该长什么样、以及大概要做什么。
> 这份文档会随着调研和讨论持续生长。

---

## 一、为什么要做社区货币

### 问题

在社区里，人和人之间有大量的交换在发生——办活动、提供住宿、分享技能、互相帮忙。这些东西有价值，但它们没有被「记录」下来，也没有一个让价值在内部流动的媒介。

现有的解决方案有问题：
- **用钱结算**：把人和人的关系变成交易关系。本来是无偿的善意，一旦开始记账就变味了。
- **纯礼物经济**：很好，但缺少一种方式让「我帮了你」可以被看见、可以被传递。礼物经济依赖强关系和持续的记忆，在规模稍大的社区里容易断。
- **不记录**：那就只有当事两个人知道。社区看不到这些交换，也无法基于它们生长出新的东西。

### 我想要的东西

一个**内部的、轻量的、不被异化的**价值流通媒介。它：

- 让社区里的交换可以被看见
- 让「我帮了你」可以流动——你不需要直接回报我，你可以回报给社区里的另一个人
- 不是工资、不是量化、不是对人的替代

## 二、它是什么，它不是什么

### 它是

- **内部债务 / 内部信用**：A 帮了 B，系统记录一笔 B 欠社区的 credit。这笔 credit 不是 B 欠 A 个人的——A 得到的是社区的 credit，可以在社区内花掉。
- **小规模流通**：在一个具体的群体里（一个群、一个共学、一个线下社区），不是通用货币。
- **可被创建**：每个人/每个授权组织都可以创建自己的货币，设定自己的锚定和规则。
- **礼物经济的辅助层**：不是替代礼物经济，而是在礼物经济上加一层可见的、可传递的记录。
- **鼓励负债**：在系统里有负余额不是坏事——它意味着你从社区得到了帮助。系统不追求每个人都归零。

### 它不是

- **不是金钱的替代品**：不应该和人民币锚定。它的价值来自社区内部的约定，不是来自外部市场。
- **不是工资**：不是为了衡量劳动价值。一个小时陪聊和修水管不能也不需要比较。
- **不是量化的异化**：不追求把所有东西都变成数字。数字只是辅助记忆和流动，不定义价值。
- **不是对善意和交流的替代**：我们不是要把「我无偿帮你」变成「我帮你以换取积分」。数字是影子，关系是实体。

## 三、核心机制设想

### 3.1 多货币、各自锚定

不是一个大一统的社区货币，而是**每个人/每个组织都可以创建自己的货币**。经过申请和授权的人可以开通自己的货币组织，自己设定：

- **叫什么**（俏也币？泡泡币？共学豆？）
- **锚定什么**——它可以锚定具体的东西，也可以不锚定：
  - 一个饭票（等价于一餐饭）
  - 一个住宿（等价于一晚住宿）
  - 一些徽章/纪念品（像抗战老兵社区的战争徽章）
  - 或者干脆不锚定，就是社区内部的信用记账
- **发行规则**：谁可以发、怎么发
- **使用范围**：在哪个群里流通

### 3.2 信用 / 债务模型

核心是 **mutual credit（相互信用）**，不是 token：

- 每个人的账户可以正也可以负
- 交易发生时：A 给 B 提供服务 → A 账户 +N，B 账户 -N
- 系统不要求有「储备金」，信用是参与者之间共同创造的
- 负余额不是「欠钱」，是「社区给了你东西，你也会给回去」

这和 LETS（Local Exchange Trading System）的逻辑一致：不是先有货币再交易，而是交易本身创造了货币。

### 3.3 以俏也为中心，慢慢加人

第一阶段的实验：

1. **俏也的个人货币**：
   - 俏也办活动 → 参与者不用付门票，获得俏也币
   - 有人给俏也提供免费住宿 → 俏也给他们 credit
   - 持有俏也币的人可以加入俏也的「组织」，用币换取俏也提供的东西（什么？待定）

2. **在群里运行**：
   - 大家在群里写「我可以提供什么」「我想要什么」
   - 交易通过群内记录
   - 不需要复杂的 App，一开始可以就是一个共享表格或简单的微信小程序

3. **慢慢扩展**：
   - 有人觉得好用，申请开通自己的货币
   - 不同货币之间怎么兑换？——先不解决，先各自运行

### 3.4 做人共学场景

（详见 `../做人共学/进击的人类！做人共学.md`）

- 大家付费进入共学 → 获得共学货币
- 在共学内部互相购买彼此的服务/产品
- 货币留在共学范围内，不提现
- 鼓励交换、许愿、悬赏、打赏
- 目标是形成一个内部 give & take 的紧密流动圈

## 四、使用场景（目前的设想）

### 场景 1：俏也的个人交换圈

- 俏也办分享会/活动 → 大家用交换代替付费 → 俏也发币
- 经常有人给俏也提供免费住宿 → 俏也想给他们 credit → 他们可以在俏也的圈子里换东西
- 俏也自己有什么可以提供？——待讨论（咨询？活动优先权？zine？）

### 场景 2：做人共学

- 付费进入 → 获得初始货币
- 内部互相买卖：有人做设计、有人写文案、有人做咨询、有人教技能
- 用币悬赏/许愿："我需要一个人帮我看看这个方案"→ 有人接 → 币流转
- 打赏感谢：看到别人做了好东西 → 打赏币

### 场景 3：线下常住社区

- 大家在一个地方常住（比如屏南龙潭村、CYC 共居社区）
- 有一个内部流通的货币
- 可以交换的东西：借工具、帮忙看家、代买东西、一起做饭、教技能、分享物资
- 如果大家都在一个地方，交换的频次和种类会更多

## 五、设计原则 / 倡导

这些不是技术约束，而是**价值观约束**。如果做出来的东西违背了这些，那就做错了。

1. **不被异化**：数字是影子，关系是实体。不要让数字定义关系。
2. **不替代善意**：不是把礼物经济变成记账。是给礼物经济加一层可见性。
3. **不与金钱锚定**：不追求和人民币 1:1。价值来自社区内部约定。
4. **不追求归零**：负余额不是坏事。鼓励负债——这意味着有人在社区里得到了帮助。
5. **小规模**：不追求做大。越小越有意义。
6. **可创建**：每个人都可以创立自己的货币，不需要中心化审批。
7. **鼓励流动**：货币应该花出去，不是存起来。参考 Wörgl 实验的 stamp scrip 逻辑（不用就贬值）。

## 七、需要讨论的问题

> 这些是我还不确定的事，需要进一步讨论。

1. **锚定还是不锚定？**
   - 如果锚定饭票/住宿/徽章，会不会限制了灵活性？
   - 如果不锚定，大家会不会不知道「一个币值多少」？
   - 也许不同货币可以不同策略？

2. **负余额的上限？**
   - 如果鼓励负债，要不要设上限？
   - 怎么防止有人只索取不付出？（还是不需要防止？）

3. **技术实现？**
   - 先用共享表格？微信小程序？还是需要开发？
   - 需要什么样的功能：创建货币、记录交易、查看余额、发布 offer/need？

4. **多货币之间怎么互通？**
   - 俏也币和共学豆能不能互换？
   - 如果可以，汇率怎么定？

5. **和「做人共学」的具体结合？**
   - 货币怎么发？初始分配多少？
   - 花不完的怎么办？

6. **要不要参考 Wörgl 的 demurrage（持有税）？**
   - 即货币不用就贬值/过期——鼓励流通
   - 但会不会让人感到压力？
