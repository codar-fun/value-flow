# 后端交付：H01–H09 接口契约（2026-10-07）

对应 `improvement.md` 的 H01–H09。后端是 loop-backend 的 `flow-backend` 代码，生产地址 `https://flow-api.sola.day/api`。前端代理路径单独标出。身份一律从 session 推导，不信任客户端传入的身份。

- **后端版本**：镜像 `registry.sola.day/sola/flow-backend:h01h09-20261007b`，2026-10-07 上线。迁移 `20261007120001` 先于代码执行，只新增表和列。
- **同时修复**：设为"仅对方可见"（hidden）的好人卡以前对同圈成员也可见，现在只有写卡人和收卡人能看到。
- **测试**：后端 165 项（新增修订、发布、邀请、发现权限、分享、管理员与期初积分 6 组接口测试，以及领域测试）；前端 29 项（含生产构建）。
- **错误格式**：`{"error": {"code": "...", "message": "可直接展示的中文"}}`。校验失败的 `message` 是第一条具体原因（如「描述最多 2000 个字」），`fields` 里是全部原因；不会静默截断。

## H01 统一记账规则

- 每个圈子的 `settings` 固定为 `allow_negative_balance: true`、`require_confirmation: false`、`allow_reject_correct: true`。创建和 `PATCH /circles/:id` 无论传什么都会被覆盖，bootstrap 返回实际存储值。
- 圈主仍可改：`name`、`icon`、`description`、`currency`、`joining`（`approval`/`direct`）、`discoverability`、`settings.references`、`settings.rules`。
- 记录由任一当事人记下即 `confirmed` 入账并通知另一方，不再产生待确认记录；幂等键（BE05）照旧。

## H02 双人修订与撤销

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/records/:id/revisions` | `{kind: "edit"\|"revoke", base_version?, amount?, title?, story?, visibility?}` → 201 `{revision, record}` |
| POST | `/records/:id/revisions/:revision_id/resolve` | `{action: "accept"\|"decline"\|"withdraw"}` → `{revision, record}` |
| GET | `/records/:id/history` | 仅当事人：`{record, revisions: [...]}`，按时间正序 |

- 修订对象：`id/revision_id, record_id, kind, base_version, old_values, new_values, proposed_by_id, status(pending/accepted/declined/withdrawn), resolved_by_id, created_at, resolved_at`，时间均为服务端时间。
- `edit` 只记录真正变化的字段；只改正文时标题按第一行重新生成；金额不变、只改文案或只改可见范围都可以单独提议。
- 同意前原记录和余额不变；拒绝或撤回不改账。同意 `edit` 在同一事务里按差额调整双方 `balance/given/received`；同意 `revoke` 按**当前有效金额**整笔冲销，记录变为 `rejected` 并保留。每次同意 `version + 1`。
- 错误：第三方 / 自己批自己 / 非发起人撤回 → 403；已有待决提议 → 409 `revision_pending`；重复处理 → 409 `revision_not_pending`；`base_version` 过期 → 409 `version_conflict`；没有改动 → 422 `no_change`；已撤销记录再提议 → 422 `not_correctable`。并发同意同一提议只成功一次。
- **旧接口**：`PATCH /records/:id {action:"reject"}` 现在返回 409 `revocation_needs_consent`，不再立即冲销；`{action:"correct"}` 与 `POST /records/:id/correction` 转成上面的修订流程。
- bootstrap 的记录新增 `version`、`pending_revision`。**只有当事人收到 `pending_revision`**（其中可能含尚未同意公开的正文），第三方看到的是 `null`；`pending_correction` 继续由待决的 edit 修订生成，供旧客户端使用。
- 当事人离圈时，未决修订自动以 `withdrawn` 结束，并保留在历史里。
- 前端代理：`POST /api/records/:id/revisions`、`POST /api/records/:id/revisions/:revisionId`、`GET /api/records/:id/history`。

## H03 单段文本与头像

- 记录：只传 `story`，`title` 可空，服务端取第一个非空行的前 60 个字符（按字形计算，中文和 emoji 都算一个）。上限：`story` 2000、`title` 80，超出返回 422，不截断。
- 发布：只传 `detail`，规则同上。上限：`detail` 2000、`title` 120、`reference` 200。
- 头像：`PATCH /me` 原样保存 `avatar` 字符串（≤255），bootstrap 原样返回，例如 `buddy3:shape:expression:color:accentColor`。

## H04 需要/提供编辑

- `PATCH /listings/:id`，字段可以是 `title, detail, reference, visibility(circle|cross-circle), circle_ids, status` 中的任意组合，**只有发布者本人**可以修改（否则 403）。
- 未知字段返回 422 `unknown_fields`（带 `fields` 列表），不会出现返回 200 却没写入的情况。校验和写入在同一个 changeset 里完成，不会只写入一部分。
- `circle_ids` 必须是自己当前加入的圈子，否则 422 `not_a_member_of_circle`。回读时原样返回提交的 `circle_ids`（去重、保持顺序），`cross-circle` 不会被展开成"全部圈子"。`visibility` 为 `circle` 时至少要选一个圈子。
- 暂停或结束后从他人列表消失；恢复后重新出现。`closed` 是终态，不能再编辑或恢复（422 `listing_closed`）。响应带 `created_at` 和 `updated_at`。
- 新建发布同样校验圈子成员身份（以前不校验）。

## H05 邀请

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/circles/:id/invitations` | `{type?: "regular"\|"owner_direct", ttl_seconds?}` → 201 `{id, token, path, type, status, expires_at, max_uses: null, used_count, ...}` |
| GET | `/circles/:id/invitations` | 圈主看到全部有效邀请，其他成员只看到自己发的（不含 token） |
| DELETE | `/invitations/:id` | 创建者或圈主撤销 |
| GET | `/invitations/:token/preview` | **无需登录**，`Cache-Control: no-store`；不消耗 token、不加入、不申请 |
| POST | `/invitations/:token/accept` | 登录用户主动加入 |

- **普通邀请**：任何成员都能签发；7 天有效，人数不限，按圈子的 `joining` 规则加入。**圈主专属邀请**（`owner_direct`）只有现任圈主能签发，否则 403；凭它加入免审批，也会把已经在等审批的人直接转为成员。
- `ttl_seconds` 可设为 60 秒到 7 天，用来实际测试过期。
- 预览返回 `type, expires_at, joins_as(active|pending), circle{name, icon, description, currency, joining, discoverability, member_count, rules, references, settings}, inviter{display_name, handle}, viewer_status`。不返回成员名单、联系方式、余额或记录。
- 不存在、过期、已撤销的邀请统一返回 410 `invalid_invite`，无法从返回结果区分是哪种情况。
- 同一个人重复接受：不会产生重复的成员关系或申请，`used_count` 只加一次，圈主也只收到一次通知。多人同时接受同一链接都能成功。审批制圈子里，圈主收到的通知类型是 `join_request`（以前是 `invite`）。
- 圈主转让时，旧圈主签发的专属邀请自动撤销；普通邀请不受影响。
- 前端：`/join/:token` 先显示预览，用户点击后才加入；未登录时先登录，登录后回到预览页，**不会自动接受**。

## H06 发现权限、访客介绍、查看者档案

- 圈子新增 `discoverability`：`public` 或 `invite_only`，默认 `invite_only`，和 `joining` 相互独立。
- `GET /circles` 只返回公开圈，以及自己已加入或正在申请的圈。仅凭邀请的圈不能通过 `POST /circles/:id/join` 加入（403 `invite_only`），只能用邀请链接。
- `GET /circles/:id`、`/members`、`/feed`、`/leaderboard` 只对成员开放，非成员一律返回 404，和圈子不存在时一样，无法枚举。
- `GET /circles/:id/preview`：非成员可以看到名称、图标、完整介绍、约定、参考、人数、加入方式，以及 `membership_status`、`can_apply`。不带成员、联系方式、余额、记录。仅凭邀请的圈对外人返回 404。
- `GET /members/:id/profile?circle_id=`：查看者从 session 取。返回 `shared_circle_ids`、只限共同圈的 `accounts` 和 `stats{posted_records, mystery_records}`（服务端统计，包含查看者读不到正文的记录）、联系方式（只在有共同圈时返回）、`other_discoverable_circles`（对方所在的公开圈，排除共同圈）、对查看者可见的发布和好人卡。没有共同圈时 `accounts=[]`、`stats=null`。
- bootstrap 的每个圈子新增 `stats{posted_records, mystery_records}`（全圈总数）和 `discoverability`。

## H07 主动公开分享

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/shares` | `{kind: "listing"\|"record"\|"good_card", target_id}` → 201 `{token, path: "/s/<token>"}` |
| GET | `/shares/:token/preview` | 无需登录，`no-store`，只返回这一条内容的最少字段 |
| DELETE | `/shares/:token` | 只有创建者能收回 |

- 谁能分享：发布只能由发布者本人分享，而且必须是进行中、非私密的；记录只能由当事人分享，而且必须已入账、公开、没有待决修订（神秘或私密记录返回 422）；好人卡只能由**收卡人**分享，写卡人不行。
- 每次读取都会重新检查源内容。发布暂停或结束、记录撤销、好人卡隐藏，或者链接被收回，都返回 410 `share_unavailable`。内容编辑后，链接显示最新版本。
- 公开内容只有名字和头像，不含联系方式、地址、余额。
- 前端：分享面板在符合条件时提供"生成公开链接"，复制、二维码、系统分享都用同一个 URL，也可以收回；访客页面是 `/s/:token`。

## H08 通知

- 修订相关的通知带 `record_id` 和 `revision_id`：`revision_proposed`（`text` 为 `edit` 或 `revoke`，`amount` 为提议的新金额）、`revision_resolved`（`text` 为 `accepted`、`declined` 或 `withdrawn`），发给没有操作的那一方。
- 邀请加入审批制圈子时，圈主收到 `join_request`。
- 时间都是服务端时间（`created_at`）。

## H09 平台管理员与期初积分

**开通与重置**：只能由维护方操作，不通过 API。在生产容器里执行：

```
docker exec $(docker ps -q --filter ancestor=registry.sola.day/sola/flow-backend:<标签>) \
  /app/bin/loop eval 'Loop.Release.create_admin("名称", "至少 12 位的密码")'
# 重置：Loop.Release.reset_admin_password("名称", "新密码")   停用：Loop.Release.disable_admin("名称")
```

重置和停用都会立即注销这个管理员的所有会话。密码用 PBKDF2-SHA256 存储（21 万次迭代、独立盐），比较时用常量时间。

**认证**：

- `POST /admin/session {password}` → `{access_token, expires_in: 900, admin{name}}`。
- 失败返回 401；同一 IP 15 分钟内失败 5 次、或全局失败 50 次，返回 429。
- 之后的请求用 `Authorization: Bearer <admin token>`，每次都会核验。
- `GET /admin/session` 查看登录状态；`DELETE /admin/session` 注销。
- 会话 15 分钟后过期，不自动续期。
- 成员 token、圈主身份都调不动 `/admin`；管理员 token 也调不动成员接口。

**接口**（与前端文档"精确接口与响应"一致）：

| 方法 | 路径 |
|---|---|
| GET | `/admin/circles?q=&cursor=` → `{circles: [{id, name, currency}], next_cursor}` |
| GET | `/admin/circles/:id/members?cursor=` → `{members: [{account_id, display_name, username, balance, opening_balance, opening_balance_initialized}], next_cursor}` |
| POST | `/admin/circles/:id/opening-balance-imports/preview` → `{preview_id, expires_at, total, entries: [{account_id, display_name, current_balance, opening_balance, resulting_balance}]}` |
| POST | `/admin/circles/:id/opening-balance-imports/:preview_id/confirm` `{idempotency_key}` → `{batch}` |
| GET | `/admin/circles/:id/opening-balance-imports?cursor=&preview_id=` → `{batches, next_cursor}` |
| GET | `/admin/circles/:id/opening-balance-imports/:batch_id` → `{batch}` |
| POST | `/admin/circles/:id/opening-balance-adjustments` `{account_id, opening_balance, reason}` → `{adjustment}`（受控纠错） |
| GET | `/admin/circles/:id/opening-balance-adjustments` |

**业务规则**：

- 只能给这个圈子的在册成员发放，不会自动拉人入圈。每人只能初始化一次，填 0 也算一次。
- 期初积分加到 `balance` 上，叠加在已有的互助净额之上，不会覆盖；不计入 `given/received`，批次总额也不需要为零。
- 一批最多 500 人，每人金额在 ±1,000,000 以内，必须是整数。逐行错误返回 422 `invalid_entries`，带 `rows: [{index, account_id, message}]`，整批都不写入。
- 预览有效 30 分钟，绑定预览时每个人的余额快照和初始化状态。确认时会在行锁下复核：如果期间有人退出、已被初始化或余额有变动，返回 409 `stale_preview`。
- 同一预览重复确认或并发确认，都返回同一个批次，不会重复加分。同一个批次键不能用于第二批（409 `idempotency_key_used`）。
- 纠错：只能修改已初始化成员的期初值，按差额调整余额，原批次保持不变。每次修正都会记录旧值、新值、原因、操作者和时间。

**前端**：

- `/admin` 只有在进程设置了 `FLOW_ADMIN_ENABLED=true` 时才存在。生产 `ginger.yml` 没有设置这个变量，所以线上主站没有管理入口，`/admin` 返回 404。
- 本地使用：设置 `FLOW_ADMIN_ENABLED=true`，并把 `LOOP_ADMIN_API_BASE` 指向 `https://flow-api.sola.day/api`。
- 管理员 token 只存在独立的 HttpOnly、SameSite=Strict cookie `flow_admin` 里；写请求必须同源。

## 本地联调证据（2026-10-07）

本地真实后端 `mix phx.server` 加本地生产构建前端 `vinext start`，不连生产库，用 A、B、C 三个独立浏览器会话：

1. A 建圈：第 2 步只显示固定规则，第 3 步默认"管理员审批 + 仅凭邀请"。库里存的是 `approval / invite_only / 固定三规则`。
2. A 生成普通邀请：显示真实到期时间和"7 天内可供多人使用"。B 未登录打开，预览显示圈名、约定、加入方式、邀请人，`used_count` 仍为 0。B 点击后先登录，登录后**回到预览页而没有被加入**，再点"申请加入"后变为 pending，`used_count` 变成 1，圈主收到 `join_request`。A 放行后 B 成为成员。
3. A 记一笔 4（多行描述，含 emoji），立即得到 +4/−4，标题由第一行生成。A 申请改成 6，余额不变；B 从通知直接定位到这条记录并同意，余额变为 6/−6。B 申请撤销，A 同意后双方余额、给出、收到都回到 0，记录显示"已撤销"，修改记录里能看到两次申请和各自的时间。
4. A 发布"我可以给"（只有一段描述），编辑后回读一致；生成公开链接，C 不登录就能打开 `/s/…`；A 暂停后链接失效，恢复后又能打开。
5. C 打开 `/admin`：错误密码被拒；登录后选圈，填 alice=300、bob=80，预览时账本不变，确认后变为 300/80，`given/received` 仍为 0；成员行显示"已发放，不能再次填写"，历史批次可以查到。
