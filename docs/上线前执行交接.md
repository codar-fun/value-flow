## 三 立即执行的前端工作

### F1 登录续期与故障恢复

检查 `app/lib/loop.ts`、`app/api/bootstrap/route.ts`、认证代理和页面错误状态。目前 refresh 遇到任何非成功响应就清 cookie，临时后端故障也会被当成失效登录。

完成以下行为：

- 按可确认的认证错误契约区分“凭证确实失效”与限流、5xx、网络中断、超时和非法响应；未知错误不武断清除登录。
- 临时故障保留会话，返回明确可恢复的错误；页面显示重试状态，不切成首次注册或空白匿名世界。
- 为上游请求设置合理的超时和错误处理。不要自动重放创建记录、接受邀请等写请求，避免服务端已写入但响应丢失时产生重复副作用。
- 保留当前同进程续期合并；用测试验证同一会话并发刷新不会互相清 cookie。不要声称这个内存机制解决了跨进程或多实例竞争，后者归入后端交接。
- 保持 HttpOnly、Secure、SameSite 等既有会话保护与生产 OTP 行为。

验收：用隔离的上游 stub 或 mock 自动化覆盖 refresh 成功、已确认的失效凭证、429、503、超时、响应格式错误及并发；检查响应状态、cookie 与界面状态。模拟结果标注为前端故障处理测试，不算真实后端验收。再用真实测试账号验证正常登录、刷新页面、退出和重新登录。

### F2 构建打包范围

检查 `Dockerfile` 的整目录复制与 `.dockerignore`。排除本地 `.dev.vars`、私密环境文件、评审临时材料、浏览器会话、测试邮箱凭据、日志、截图和 agent 临时目录；先核实构建依赖，保留确实需要的配置和资源。

验收：证明敏感或临时路径不进入构建上下文及最终镜像。可在隔离副本使用不含秘密的哨兵文件验证。若没有 Docker，只报告静态排除检查与构建结果，将镜像内检查标为未验证。不要输出真实凭据，不把“存在风险”写成“已经泄露”。

### F3 登录后返回与关键界面流程

通过自己新注册的账号验证邀请、个人档案、动态三个入口：未登录打开链接，完成 OTP 和首次资料填写后，能返回原目标；刷新、登录过期、失效链接都有准确反馈。自动接受邀请须符合现有用户确认流程，不能因预览或登录意外消耗 token。

复查通知入口、确认与更正弹窗、发布按钮、加载失败重试、空状态、移动端软键盘与底部安全区域。修复能从当前代码和复现确认的前端问题。已存在的通知可点击、sticky 提交按钮等先验证再修改。

拒绝记录缺失、通知缺少 record_id、邀请预览接口缺失时，按后端交接登记。不要构造虚假记录、根据金额强行匹配目标，或从不透明 token 编造圈名。旧通知存在多条候选时采用不误导的列表入口或提示，具体定位仍标为后端阻塞。
