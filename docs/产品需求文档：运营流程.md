## 1. 产品要回应的问题

现实中的分享、住宿、咨询、照料、技能交换和举手之劳，大多已经在微信或线下发生。产品不替代这些关系，也不要求所有善意都被记录。它只提供一层轻量的社区记忆：

- 让已经发生的互助可以被轻松记下，并在社区内形成可流通额度；
- 让成员更容易说出“我想要什么”和“我可以给什么”；
- 让看不见的善意可以通过好人卡被看见，并跟着一个人跨圈流动；
- 让不同圈子自由定义自己的货币、成员边界、参考物和规则；
- 让记录尽量像“对一个熟悉的社区伙伴说一句话”，而不是填写表格或操作银行应用。

产品的基本态度是：**数字是影子，关系是实体。没有记录的善意仍然成立。**

## 2. 本轮成果

### 2.1 需求文档

本文件描述运营流程、产品对象、页面、交互状态、可见范围和静态 Demo 验收标准。后续开发人员可基于它补充技术方案，但不应把本轮原型中的假数据和简化动作误解为后端设计。

### 2.2 静态 Demo

静态 Demo 用同一套产品界面展示三个示例圈子：

1. 俏也的个人交换圈；
2. 做人共学；
3. 线下常驻社区。

它们不是三个产品，而是“任何人都可以自由建圈”的三个实例。一个人可以创建、管理、加入多个圈子。

### 2.3 文档使用边界

本文件定义正式产品要满足的规则；[`开发交付说明.md`](开发交付说明.md) 解释当前静态页面已经演示了什么、哪些动作只是视觉反馈，以及哪些状态尚未持久化。两者必须一起阅读，不能把静态简化当成正式权限或数据方案。

## 3. 核心概念

### 3.1 平台

平台提供通用的表达方式、基本规则和跨圈个人身份。打开产品后，不先进入宣传首页，而是直接看到“我加入的圈子的动态”。

### 3.2 圈子

圈子是成员、货币和交易的边界。

- 每个圈子的成员独立；
- 每个圈子的货币和余额独立；
- 圈子可以采用平台通用规则，也可以补充自己的介绍和规则；
- 创建者可以建立多个圈子；
- 同一个人可以加入多个圈子；
- 本轮不做不同圈子货币之间的兑换。

### 3.3 好人卡

好人卡是单向认可，不是货币：

- 由接收帮助的人主动发出；
- 必须写清楚发生过什么；
- 显示发卡人姓名；
- 不产生任何余额和偿还义务；
- 默认跟随接收者跨圈公开；
- 接收者可以隐藏自己不想展示的卡；
- 好人卡不会变成积分、排名或可兑换资产。

### 3.4 圈内互助额度

圈内互助额度是完成互助之后产生的可流通额度：

- A 为 B 提供互助后，A 增加额度，B 减少额度；
- 额度属于圈子，不属于平台全局；
- 负余额意味着“我曾接受社区帮助”，不等于信用污点；
- 交易只记录已经完成的事情；
- 未完成的需求和提供不会改变余额。

### 3.5 锚定物与参考物

- 创建圈子时可以设置，但不是必填；
- 可以后续添加；
- 一个圈子可以有多个参考物；
- 例如“一顿饭”“一晚住宿”“半小时小忙”；
- 参考物只是协商辅助，不形成平台统一价格；
- 社区讨论后，由管理员直接更新参考物和说明；
- 本轮不做站内提案或投票系统。

### 3.6 我想要 / 我可以给

两者是同一种“社区帖子”的两个方向，不建立两套产品：

- 发布时选择“我想要”或“我可以给”；
- 可以文字输入，也可以直接说一句话；
- 可选择仅一个圈可见、多个圈可见或跨圈公开；
- 可设置时间、地点、参考额度，但都不是强制字段；
- 不做站内聊天、报价、接单和履约状态；
- 感兴趣的人进入发布者主页，点击“联系”查看微信号，再私下沟通；
- 每条内容可一键生成适合分享至微信群的图片。

## 4. 角色

### 4.1 普通成员

- 查看自己加入圈子的综合动态；
- 发布需要或提供；
- 查看同圈成员资料和联系方式；
- 记录已经完成的互助；
- 给别人发好人卡；
- 查看自己的跨圈身份、余额和记录；
- 对涉及自己的记录提出修改或拒绝。

### 4.2 圈子创建者 / 管理员

- 创建圈子并写圈子介绍；
- 设置准入方式；
- 邀请或审批成员；
- 设置和修改货币名称、锚定物、参考物和圈子规则；
- 发起历史交易补录；
- 在必要时协助处理更正和争议。

### 4.3 社区 Agent

Agent 在界面中不是后台工具，而是一个社区引导角色。暂名“泡泡助手”。

- 接住用户的一句话、语音或未来可能上传的截图；
- 判断用户想做的是交易记录、历史补录、需要、提供还是好人卡；
- 生成可检查、可修改的草稿；
- 不未经确认直接替用户发布；
- 用社区语言解释记录结果，不使用审计、征信、扣款等金融化措辞。

## 5. 运营阶段

### 5.1 种子期

第一批成员是创建者已经认识并发生过交换的人。

建议顺序：

1. 创建圈子；
2. 写一张清楚、有感染力的圈子介绍页；
3. 通过微信私聊或群聊邀请种子成员；
4. 种子期邀请链接可以直接加入，不要求管理员逐个审批；
5. 发起过去交易的补录；
6. 邀请大家用语音填写“我想要”和“我可以给”；
7. 用分享图把需要和提供重新带回微信群；
8. 开始记录新的、已经完成的互助。

### 5.2 扩大期

- 圈子可以切换为“加入需管理员审批”；
- 仍然可以由成员发出邀请，但受邀者需要通过审批；
- 不同圈子可以选择不同准入方式；
- 加入圈子不等于承诺为所有成员提供服务；任何人都可以拒绝具体请求。

## 6. 核心用户流程

### 6.1 统一的“说一句”入口

首页提供最突出的“说一句”入口。用户不必先寻找正确表单。

可能的输入：

- “记一下，昨天小王让我住了一晚，算 10 个泡泡。”
- “我最近需要一个人帮我看看文案。”
- “我可以给大家做一次肩颈按摩。”
- “给小王一张好人卡，她上周陪我去了医院。”

Agent 判断类型并生成相应草稿，用户检查后确认。

### 6.2 历史交易补录

1. 管理员或当事人说出过去发生的互助；
2. Agent 提取圈子、双方、事情、时间和额度；
3. 发起人检查草稿；
4. 发起人确认后立即录入；
5. 对方收到通知；
6. 如果对方还没有加入圈子，确认邀请即默认加入；
7. 种子期无需审批，扩大期按圈子准入规则处理；
8. 对方之后可以修改或拒绝。

补录的是圈内额度，不是人民币债务。

### 6.3 新交易记录

1. 真实协商发生在微信群、微信私聊或线下；
2. 事情完成后，其中更熟悉系统的一方打开产品；
3. 用户说一句话或古法填写；
4. Agent 生成记录草稿；
5. 任意一方确认即可立即入账；
6. 另一方收到通知，不需要额外确认；
7. 另一方可以不操作、提出修改或拒绝。

这是“先记录、后纠正”的轻量账本，不是双方审批后才入账的账本。

### 6.4 修改、撤回与拒绝

- 任意一方可以发起修改或撤回；
- 修改内容需要另一方确认后生效；
- 修改生效后，额度自动重算；
- 若另一方拒绝一笔首次由单方记录的交易，交易立即撤销，额度立即恢复；
- 被拒绝或更正的原记录保留状态痕迹，但不进入正常公开交易流；
- 管理员仅在争议或成员失联时协助，不能随意修改成员账目。

### 6.5 发布需要或提供

1. 用户点击“说一句”或“发布”；
2. 说出或填写内容；
3. Agent 识别为“我想要”或“我可以给”；
4. 用户选择可见圈子、是否跨圈、可选的时间地点和参考额度；
5. 发布后进入相关圈子的综合动态；
6. 用户可以一键生成分享图并转发到微信群；
7. 感兴趣的人进入发布者主页；
8. 同圈成员点击“联系”后查看微信号，私下沟通。

### 6.6 发好人卡

1. 用户说“给某人一张好人卡”或点击发卡；
2. 必须填写具体发生的事情；
3. 发卡人确认后立即出现在接收者的跨圈个人主页；
4. 卡片默认跨圈公开；
5. 接收者可以隐藏；
6. 卡片不显示金额，不改变任何余额。

## 7. 信息可见范围

### 7.1 个人主页

任何人可以看到：

- 未隐藏的好人卡及具体故事；
- 发布者选择跨圈公开的需要；
- 发布者选择跨圈公开的提供。

同圈成员额外可以看到：

- 点击“联系”后展示的微信号；
- 该成员在本圈的当前余额；
- 该成员在本圈的累计给出和累计收到；
- 该成员在本圈的公开交易；
- 仅对本圈公开的需要和提供。

本人查看自己时还可以看到私密交易、隐藏内容和所有管理入口。

### 7.2 交易可见档位

进入圈内公共动态的交易只保留两个展示档位：

1. **圈内公开**：双方、额度和事情说明对圈内成员可见；
2. **神秘记录**：圈内动态保留交易类型、额度和时间，隐藏双方身份和具体故事。

此外可以存在“仅当事人”记录：它只进入双方自己的档案，不进入圈内公共动态。本人可以查看自己的私密、撤销与更正记录。正式开发必须在服务端执行这些权限，不能只靠前端隐藏。

示例：

> 圈里刚刚发生了一次住宿互助 · 20 个泡泡  
> 参与者和故事选择了隐藏。

### 7.3 余额表达

页面同时显示三个数：

- 当前流动额度；
- 我向社区给出过；
- 我从社区收到过。

它既保留清晰账本，也避免只用一个正负数字定义成员。

## 8. 页面结构

### 8.1 手机端首页：我的圈子动态

打开产品后直接进入综合动态：

- 当前身份与跨圈好人卡提示；
- 已加入圈子的切换与余额概览；
- 突出的“说一句”入口；
- 公开交易；
- 神秘交易摘要；
- 我想要；
- 我可以给；
- 底部导航：动态、发现、圈子、我的。

### 8.2 发现页

需要和提供混在同一条信息流，通过标签和筛选区分。是否采用更复杂的分栏，待静态 Demo 完成后凭实际体验判断。

### 8.3 圈子页

- 圈子介绍；
- 货币名称；
- 多个参考物；
- 本人余额；
- 圈子动态；
- 成员；
- 加入和联系规则；
- 管理员入口。

具体排序暂不锁死，由静态 Demo 帮助判断。

### 8.4 我的页面

- 跨圈身份；
- 我创建和加入的圈子；
- 好人卡故事；
- 所有需要与提供；
- 各圈余额；
- 公开和隐藏设置。

### 8.5 电脑端

电脑端使用同一套完整功能，并预留更宽的圈子运营视图。详细 dashboard 暂不在本轮确定，只放轻量占位。

### 8.6 整体概念页

从左上角品牌标识或手机端“流”图标进入，用来解释：

- 产品的一句话定位；
- 圈子、互助额度、需要/提供、好人卡四个对象的区别；
- 一次线下或微信互助如何成为记录；
- 示例圈子与产品边界；
- 不兑换、不排名、可以拒绝和可以退出。

### 8.7 创建圈子页

创建圈子使用四步应用内页面：圈子身份、互助设置、成员与边界、预览确认。用户要能设置圈子名称、额度名称、介绍、场景、参考物、加入方式、交易展示方式、神秘记录和退出规则。正式产品保存后应创建圈子、初始成员关系、账户规则与邀请入口；静态 Demo 只展示完成状态。

## 9. 分享图

需要和提供都可以生成 Neo-brutalism 风格的分享图。分享图顶部集中展示发布者目前仍有效的需要和提供，而不是只展示单条内容；底部包含小程序码或网页二维码。

建议内容：

- 发布者角色头像、名字和社区角色称号；
- “我目前想要”；
- “我目前可以给”；
- 所属圈子或可见范围；
- 可选地点、时间和参考额度；
- 小程序码；
- 一句轻提示：“可以问，也可以拒绝。”

## 10. 视觉与角色方向

### 10.1 Neo-brutalism

- 粗黑描边；
- 硬边投影；
- 奶油色、略带纸张温度的手机界面；
- 手机界面之外是明亮黄色点阵背景，形成“社区世界地图”的感觉；
- 高饱和黄色为主色，粉、蓝、绿、珊瑚红作为不同事件的辅助色；
- 卡片和手机外壳使用明显圆角，但仍保留粗黑边和硬边阴影；
- 大标题使用粗而略带手写感的字体，辅助信息可使用等宽字体；
- 按钮、卡片、数字盒子有明显按压感和游戏道具感；
- 页面中可以出现方形控制点、三角形、十字、网格、点阵等简单几何元素；
- 不使用企业金融产品常见的蓝白渐变、玻璃拟态和精致银行图表。

### 10.2 游戏感

- 成员使用黑白线稿角色头像，并通过称号、携带物和个人故事成为社区角色，而不是普通社交头像；
- 可有角色称号，例如“旅居交换者”“修理玩家”“饭桌召集人”；
- 圈子像不同地图或营地，但不建立竞争排行榜；
- 动态像社区世界里发生的事件；
- Agent 是可对话的社区成员，有线稿表情、角色状态和自己的位置，但不压过真人成员；
- 游戏感用于降低行动门槛，不用于积分操控、连续签到或制造焦虑。

视觉参考图只用于学习语言，不照搬其中的挑战、星星奖励和排行榜机制。原图中的“stars / winner / challenge”属于需要明确舍弃的竞争设计。

## 11. 静态 Demo 必须覆盖的故事

1. 用户在三个自己创建或加入的圈子之间切换；
2. 从综合动态看到公开交易、神秘交易、需要和提供；
3. 点击“说一句”，让 Agent 识别四种不同意图；
4. 生成并确认一条历史住宿补录；
5. 发布一条需要或提供；
6. 查看分享图；
7. 进入社区成员主页，查看角色、好人卡、余额、交易和微信联系方式；
8. 查看圈子介绍、参考物和成员；
9. 查看自己的跨圈身份；
10. 切换综合动态与三个单圈动态，并用类型筛选真实改变列表；
11. 打开整体概念页，理解四个核心对象和产品边界；
12. 完成四步创建圈子流程并看到预览；
13. 打开全部成员、圈子规则、圈子介绍和邀请成员；
14. 在自己和其他成员的档案中切换好人卡、需要/提供、互助记录；
15. 在桌面宽度下看到轻量运营侧栏或占位 dashboard。

## 12. 本轮明确不做

- 真实账号与微信授权；
- 真实语音识别、图片识别和聊天截图读取；
- 真实数据保存；
- 站内聊天；
- 报价、接单、履约和仲裁系统；
- 跨圈货币兑换；
- 人员信用分、贡献榜和排名；
- 圈内投票；
- 复杂管理员 dashboard；
- 支付、人民币换购、提现或投资功能。

## 13. 待 Demo 后再判断

- 圈子页中动态、成员、介绍和参考物的优先顺序；
- 桌面 dashboard 的详细指标；
- 神秘交易是否还需要“完全不留摘要”的第三种例外；
- Agent 最终名称和角色设定；
- 产品、好人卡和圈内额度的正式名称。

## 14. 静态 Demo 验收标准

- 手机宽度下不需要横向滚动；
- 首屏能看懂“这是我加入圈子的动态”，而不是通用宣传页；
- 一个统一入口能演示交易、需要、提供和好人卡；
- 三个圈子明确是自由建圈的实例，不被表达成三个产品；
- 好人卡和圈内额度在视觉和语言上明显不同；
