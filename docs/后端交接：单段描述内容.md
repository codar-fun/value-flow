# 单段描述内容：后端交接

日期：2026-10-03。前端测试 UI 已将「记一笔交换」「我想要」「我可以给」的标题与正文输入合并为一个描述框；「记录好事」原本就是单段故事。用户输入框不设字数上限，草稿、档案与分享图只显示一段正文。旧记录在界面上优先显示 `story`／`detail`，为空时才回退到 `title`。

## 当前兼容层

前端 `/api/records` 接收完整 `description`，向现有 loop-backend 写入时，把全文放在互助记录的 `story` 或需要／提供的 `detail`，并从首行截取最多 60 个字符填充旧 `title` 字段。这个摘要仅为兼容当前接口，不是用户填写的第二段内容，也不应在档案或分享图里重复显示。

## 后端后续需要确认和调整

1. 核对 `story`、`detail` 在数据库、请求校验和响应中的实际长度限制。前端目前不限制字数；后端若有限制，应返回明确的可见错误，不要静默截断全文。
2. 创建互助记录和需要／提供时，允许只提交一段完整描述，由后端按需生成内部摘要或让 `title` 可空。返回结果仍需提供完整正文，供动态、档案和分享使用。
3. 旧数据的 `title` 保留以兼容通知或历史调用；前端展示旧记录时优先正文、正文为空才显示标题。不要因字段迁移删除旧内容。

这里的修改是 UI 与前端适配；是否支持任意长度文本仍须由后端契约和数据库容量确认。
